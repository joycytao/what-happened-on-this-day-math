# Reusable worksheet cover pipeline

Issue #85 defines the reusable portrait cover layer. It is separate from the square thumbnail system and does not generate a month-specific doodle.

## Contract

- Page size: `1158.75 × 1500 points`, raster preview `1545 × 2000 pixels`.
- Copy: `[MONTH]`, `MORNING WORK MATH`, `DAILY WORD PROBLEMS`, `HISTORICAL MINI-STORIES`, `3 LEVELS`.
- Visual system: warm ivory background, deep navy type, orange border and rules, centered whitespace.
- The logo is the versioned SVG at `references /worksheet-assets/6pm-studio-logo.svg`; it is never regenerated by an image model.
- The pipeline retains SVG, PNG, PDF, and `cover-manifest.json` artifacts.

## Commands

```sh
npm run cover:generate
npm run cover:merge -- --config examples/worksheet-cover.example.json --source-pdf output/pdf/october-worksheet-packet.pdf --final-pdf output/worksheet-cover/october-worksheet-packet.pdf --daily-worksheet-pages 124 --answer-key-pages 3
```

Generation is allowed in `draft` status. Merge is blocked unless the config contains `approval.status: "approved"`, a non-empty `approvedBy`, and an `approvedAt` timestamp. Source and final PDFs are distinct, so rerunning generation cannot prepend a second cover to the source packet.

The final manifest records `cover_pages`, `daily_worksheet_pages`, `answer_key_pages`, and `page_count`. Issue #96 supplies the canonical reference and pixel-parity gate before a production cover is approved.
