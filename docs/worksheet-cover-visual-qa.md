# Worksheet coversheet visual QA

Issue #96 versions the canonical portrait reference and adds an objective QA gate around the reusable pipeline from Issue #85.

## Inputs and outputs

- Reference: `references /worksheet-assets/worksheet-cover-reference.png` (1102 × 1427 RGB; SHA-256 is recorded in the Issue/commit evidence).
- Candidate: deterministic PNG generated by the cover pipeline.
- Artifacts: `side-by-side.png`, `overlay.png`, `pixel-diff-heatmap.png`, and `visual-qa.json`.

## Gate

The validator resizes the candidate to the reference dimensions, computes exact per-pixel differences in fixed regions, and requires mean similarity ≥ `0.98` plus exact-pixel ratio ≥ `0.95` in every fixed region. Fixed regions cover the frame, headline, supporting copy, `3 LEVELS`, and footer/logo geometry. The candidate's original dimensions are also recorded; resizing is only for normalized comparison and does not waive output-dimension checks.

Run:

```sh
npm run cover:visual:validate -- --candidate output/worksheet-cover/october-worksheet-cover.png --prompt-version 1.0.0 --iteration 1
```

If any gate fails, do not accept the cover. Record the failed metric and artifact, optimize the prompt or compositor rule, regenerate, and rerun the complete QA suite. Every iteration must retain its prompt/layout version, checksum, diff artifacts, and JSON result. This is the required `optimize prompt/layout → regenerate → revalidate` loop.

The visible cover copy is intentionally derived from the supplied reference. `[NUMBER OF DAYS]` is a metadata variable until the canonical reference explicitly shows day-count copy; it must not be invented in the artwork.
